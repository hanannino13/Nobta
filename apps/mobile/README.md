# apps/mobile: NOBTA mobile app

This is the single React Native + Expo + TypeScript app for **Customer**, **Business Owner** and **Employee** users.

**Status:** scaffolded in M1 with `create-expo-app@5.0.0 --template default@sdk-58`: Expo SDK 58, React Native 0.88.1, React 19.3.0, TypeScript ~6.0.3. The exact versions are in ADR-013. The template's demo screens were replaced by a minimal placeholder.

Commands (run from the repo root with `-w @nobta/mobile`, or from this folder):

| Command | Purpose |
|---|---|
| `npm run android` | `expo run:android`: local Gradle development build. **Currently blocked on Windows** by the ninja path-length limit (ROADMAP U16); use the EAS workflow below |
| `npm run start` | Metro bundler for the installed development build (`--dev-client`) |
| `npm run lint` / `typecheck` / `test` | ESLint (eslint-config-expo) / `tsc --noEmit` / Jest (jest-expo) |
| `npm run doctor` | `expo-doctor` |
| `npx expo install <pkg>` | **Always** use this to add Expo/RN packages (SDK-compatible versions) |

EAS profiles live in `eas.json` (`development`, `preview`, `production`). The project is already linked to the Expo account as `@hanannino13/nobta`: `app.json` has `"owner": "hanannino13"` and `extra.eas.projectId` `e69bfa5d-fd04-4db7-b8be-5a862c7658c5`. Don't run `eas init` again.

**Android development workflow (verified in M1, ROADMAP Stage H):** install the existing EAS development build APK on the emulator (`adb install -r <apk>`), then run `npm run start` (Metro) and open the app. A new EAS build (`eas build --profile development`) is only needed when native code or native configuration changes; JS changes are served by Metro. See [infrastructure/README.md](../../infrastructure/README.md#android-emulator).

`android/` and `ios/` are generated by `expo prebuild` and ignored by Git. Configure native behaviour through `app.json` and config plugins only.

Plan:
- Expo Router (file-based) with route groups per experience: `(customer)`, `(business)` and `(auth)`. Owner and employee share `(business)`, and permissions gate the screens.
- After login, the app picks an experience from the user's memberships. A user who has both a customer profile and business memberships can switch context.
- The auth token is stored in `expo-secure-store` and never in AsyncStorage.
- i18n uses Arabic (RTL) and English (LTR). See [docs/design/DESIGN_GUIDELINES.md](../../docs/design/DESIGN_GUIDELINES.md).
- API types come from `@nobta/api-types`.
- Tests use Jest with `jest-expo` and React Native Testing Library. E2E (Maestro) is evaluated later.
